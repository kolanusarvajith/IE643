## 1. Problem

Generative models are increasingly trained on data that already contains generated images. A generative model
never copies its training data perfectly: it reproduces common, easy kinds of images more reliably than rare or
harder ones, so its output holds a little more of the common kinds and less of the rare ones. When the next model
is trained on that output, it starts from an already shifted mix and shifts it further. After a few rounds a few
kinds of images take over and rare kinds become scarce or vanish. This is the **higher-density bias** of recursive
training.

The project asked us to:

1. build a controlled, density-imbalanced dataset;
2. train a small unconditional diffusion model on it and retrain it on its own generated images for two more rounds;
3. measure how the generated distribution drifts towards the high-density part of the data;
4. propose a mechanism that reduces this bias, and show with a metric that it does.

## 2. Dataset

A subset of CIFAR-10 (32x32 images) with a controlled imbalance (100:1 between the largest and smallest class):

| Density | Classes (images each) | Images | Share |
|---|---|---|---|
| High | airplane 5000, automobile 4900, ship 4800, truck 4850, frog 4950 | 24,500 | 89.4% |
| Mid | bird 1500, deer 800 | 2,300 | 8.4% |
| Low | cat 400, dog 150, horse 50 | 600 | 2.2% |
| **Total** (D0) | | **27,400** | |

Every generated set D1, D2, D3 also has 27,400 images.

## 3. Recursive training pipeline

```
D0 (real) -> M0 -> D1 -> M1 -> D2 -> M2 -> D3
```

- **Generator:** unconditional DDPM, 24.3M-parameter U-Net (diffusers `UNet2DModel`), T = 1000 linear noise
  schedule, 20k training steps, EMA weights, images generated with deterministic 50-step DDIM.
- Every model is trained **from scratch** on the images generated by the previous one.
- All mitigation methods share M0 and D1 (on real data every weight is 1), so they differ only from M1 on.

## 4. Measuring the bias

- **Class composition:** a ResNet-18 trained on the full, balanced CIFAR-10 (with blur/noise augmentation, so it
  still recognises imperfect samples) labels every generated image.
- **Class-level metrics:** KL divergence between the generated and the original class mix, tail retention ratio
  (TRR, share of the rare classes relative to a perfect generator; ideal 1).
- **Quality and diversity:** Frechet distance (FD) and precision/recall in DINOv2 feature space, and the share of
  images that no class recognises.

## 5. Intensive assessment: class-based weighting

**Method.** Each training image's diffusion loss is weighted by `p_orig(c) / p_gen(c)` for its class c, where
`p_gen` is the class mix of the current training set (estimated by a classifier trained on D0 only), clipped and
rescaled to mean 1. Over-produced classes count less, lost classes count more.

**Results (class level).**

| Set | TRR (ideal 1) | Class KL (ideal 0) | FD |
|---|---|---|---|
| D1 (shared) | 0.526 | 0.042 | 431 |
| D2 unweighted / class-based | 0.494 / 0.578 | 0.121 / 0.063 | 755 / 709 |
| D3 unweighted / class-based | 0.523 / 0.676 | 0.284 / 0.066 | 1072 / 994 |

M0 already over-produces the common classes (94.8% of recognised images against 90.2% for a perfect generator), and
without weighting the class mix drifts further every round. Class-based weighting removes most of the extra class
KL and improves tail retention.

## 6. Novelty assessment: fixed clusters and cluster-based weighting

Class labels are too coarse to see the whole effect: one class holds many kinds of images (airplanes against a
plain sky, airplanes on a runway), and much of the shift happens between these kinds inside a class.

**Fixed density clusters of the original data.** DINOv2, a large image network pretrained without labels, turns
each image into a feature vector so that visually similar images get similar vectors. k-means (K = 30) on these
features of D0 gives 30 clusters, each one kind of image. They are computed once and **kept fixed for every
round**. A ResNet-18 trained on D0 only (with blur/noise augmentation) assigns generated images to these clusters.

- **Cluster KL:** how far a generated mix of clusters is from the original mix (0 = identical).
- **Diversity over clusters** (`e^H`, H = entropy of the shares): how many clusters the images would fill if spread
  equally. 24.6 for D0, lower when a few clusters dominate.

**Cluster-based loss weighting.** Before training the next model on a generated set D_g, each cluster gets

```
r_k = (share of cluster k in the original data D0) / (share of cluster k in the current training set D_g)
```

clipped to [0.1, 10]. The numerator is fixed; the denominator is measured again every round. Each image's weight is
the ratio of its cluster (a mix of ratios when the cluster network is unsure), rescaled to mean 1, and its term in
the diffusion loss is multiplied by it:

```
w_i = sum_k p(k | x_i) * r_k          L = (1/B) * sum_i w_i * || eps_i - eps_theta(x_i,t, t) ||^2
```

Only the loss changes; the model, training schedule and sampler stay the same, and no class labels are used.
Example from training M1: the airplane-on-sky cluster was 4.5% of D0 but 7.2% of D1, so r = 0.63 (counts less);
the largest truck cluster was 8.1% of D0 but 5.7% of D1, so r = 1.44 (counts more).

**What the clusters show.** Without weighting, the output piles up in a few clusters: an airplane-on-sky cluster
grows from 4.3% to 19.2% of the images, while the largest truck cluster falls from 8.8% to 2.0%. The recursive
amplification is driven by the distributional errors of the first generator rather than by the original frequency
ranking: clusters over-represented in D1 tend to become increasingly dominant in later rounds.

**Results (round 3).**

| | Unweighted | Class-based weighting | Cluster-based weighting |
|---|---|---|---|
| Cluster KL (lower is better) | 0.406 | 0.257 | **0.177** |
| Diversity over clusters (original 24.6) | 17.3 | 19.5 | **21.3** |
| Image quality, FD (lower is better) | 1072 | 994 | **942** |

Cluster-based weighting gives the lowest drift in every round (56% lower cluster KL than unweighted training,
against 37% for class-based weighting), keeps the most kinds of images alive, and gives the best image quality.
Because the unweighted and cluster-weighted M1 train on exactly the same images, the effect of the weights can be
isolated: each cluster's change in share relative to unweighted training follows its weight (correlation 0.78).

## 8. How to run

The notebook is written for **Kaggle** with **GPU T4 x2** and **Internet on**.

1. Upload the notebook to Kaggle (*File -> Import Notebook*).
2. In the right panel set *Accelerator: GPU T4 x2* and *Internet: On*.
3. Choose *Save Version -> Save & Run All (Commit)*.

The settings cell at the top selects the methods (`CHAINS`). The notebook is set up to reuse the models of the
intensive-phase run (M0 and the unweighted and class-based chains), added as a Kaggle dataset containing its `run/`
folder: it regenerates those chains from the saved models with the original seeds and trains the cluster-weighted
chain (about 10 h). Results are written to `run/results/` and packed into `novelty_results.zip`.

Main dependencies: PyTorch, torchvision, diffusers (>= 0.30), DINOv2 (via torch.hub, or timm as fallback), NumPy,
matplotlib (all available on Kaggle; the notebook installs diffusers).
